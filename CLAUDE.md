## Core Rules (highest priority)

1. Ask, don't assume. If anything is unclear, ask before writing a single line of code. Never make silent assumptions about intent, architecture, or requirements.

2. Simplest solution first. Implement the simplest thing that could work. Don't add abstractions or flexibility that weren't explicitly requested.

3. Don't touch unrelated code. If a file or function isn't directly part of the current task, leave it alone, even if you think it could be improved.

4. Flag uncertainty explicitly. If you're not confident about an approach or technical detail, say so before proceeding. Confidence without certainty does more damage than admitting a gap.
